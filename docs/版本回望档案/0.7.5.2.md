# 0.7.5.2 版本回望档案

## 身份

- 产品版本：`0.7.5.2`
- 技术包版本：`0.9.2`
- 基线：GitHub `main` 上已发布的 v0.7.5.0
- 性质：Python 解释器自动选择兼容补丁

## 为什么值得开发

v0.7.5.0 在真实 OpenClaw 中完成注册、自检和 migration 后，第一条“吃了个玉米”仍失败。完整证据表明请求参数、模块、依赖和数据库都正常，失败发生在 Node bridge 的进程启动层：目标 Linux 只有 `/usr/bin/python3`，旧 bridge 却固定回退到 `python`。

这是所有写入和查询共同经过的运行时入口，修复能够直接恢复整套 Skill，而不是为单句口语增加规则。

## 本版只改什么

- 非 Windows 平台的默认解释器由 `python` 改为 `python3`；
- Windows 默认仍为 `python`；
- 显式解释器和 `PYTHON` 环境变量的优先级不变；
- 同步产品/技术版本、安装说明、发布门禁和回归测试。

## 明确不改什么

- 不改 v0.7.5.0 及更早版本目录；
- 不改 Skill 业务路由、回复模板、营养计算、库存规则和安全边界；
- 不新增插件配置字段；
- 不新增 migration。

## 受保护回归点

- v0.7.5.0 的核心行为与 GF-001 至 GF-005 全部继续保留；
- 普通 Linux/OpenClaw 环境只有 `python3` 且未设置 `PYTHON` 时，七类工具仍必须能够真正启动 Python 服务；
- 用户或部署环境显式指定解释器时不得被平台默认值覆盖。
