# 食序管家 v0.7.5.0：Skill 指路边界设计

## 结论

v0.7.5.0 是从 v0.7.4.28 开始的整体重构首版。先前本地候选中出现的 `0.7.5` 和设计分支中的 `0.7.5.1` 均不作为正式产品版本；后续补丁才从 `0.7.5.1` 开始。

本版不增加饮食功能，只纠正职责边界：**Skill 给智能体路标，智能体选择正向路线，插件和业务工具守住不可突破的数据底线。**

## 根因

本地候选提交 `848dc57fe0213b72bab8d9cc5d254c4f8a62041d` 中，`direct-write-policy.ts` 按具体中文表达识别餐食、饮水、体重和入库；`before_prompt_build` 再注入具体工具、调用次数和先后顺序；`turn-guard.ts` 同时生成正向动作白名单。

这会让少数测试句稳定，却把智能体应完成的语义理解固化为持续增长的正则和分支。新的口语必须先进入短语表才能正常工作，修一个表达也容易改变另一个表达。

## 方案选择

1. **继续扩充确定性口语路由**：已证明会增加耦合，拒绝。
2. **移除全部守卫，只依赖提示词**：真实账本风险过高，拒绝。
3. **正向自治、负向护栏、工具守真**：Skill 说明判断依据和结果合同，智能体选择工具，插件只拦截明确危险，后端保证事实正确。采用。

## 职责边界

### Skill：提供路标

`SKILL.md` 只保留智能体无法从通用能力稳定推出的领域信息：

- 四个核心目标：记录摄入、管理库存、查询吃了什么、结合目标和库存提供建议；
- 判断事实是否已发生、属于谁、数量是否足够执行的观察点；
- 用户事实、包装、库存、食品库和常见估算的证据优先级；
- 可食部、自然时间、临期与过期、库存联动等领域规则；
- 工具能力、关键输入输出以及真正不可绕开的数据依赖；
- 普通餐食六项双行、纯水精简双行等结果合同；
- 查询零写入、否定零写入、安全删除、过期食品不推荐等硬边界。

代表性例子用于解释原则，不构成封闭短语表。Skill 描述“判断什么、哪些能力可用、结果必须满足什么”，不为普通正向输入编排固定工具、次数和顺序。

### 智能体：选择正向路线

智能体理解自然口语、上下文、省略、纠正和指代；判断当前事实是否足够；选择工具并根据结果决定继续、停止或补问。插件不得为普通正向输入预先选择业务域、动作或完整调用序列。

### 插件：只做负向安全护栏

插件可以拦截明确、低歧义的危险写入：

- 查询、核对、解释请求；
- 明确否定、取消、未发生、未来计划和他人行为；
- 未绑定唯一目标的删除、纠正和库存处置；
- 无有效句柄的破坏性确认；
- 成功后继续调用、相同失败原样重试和工具预算耗尽；
- 在没有跨域原子事务能力时会造成部分提交的复合写入。

插件不得根据食物名、量词或摄入动词替智能体选择正向业务域，不得为普通新增生成动作白名单，不得向提示词注入正向工具路线。普通消息未命中负向护栏时应允许智能体判断，不能因为解析器“不认识”而拒绝。

### 业务工具：保证事实正确

工具和后端继续负责 Schema、枚举、单位、时区、原子事务、句柄、幂等、库存来源、营养证据、唯一目标、只读查询和正式回执。它们约束不可接受的结果，不决定当前对话应走哪条正向路线。

## 实现范围

1. 删除 `src/direct-write-policy.ts` 及对应正向短语分类测试。
2. 移除普通正向输入的 `before_prompt_build` 私有路线注入。
3. 把 `turn-guard.ts` 的普通正向结果改为 `agent_directed`：不绑定业务域和动作；只读、否定、计划、他人、复合写入和破坏性目标仍由负向护栏处理。
4. `authorizeToolCall` 对 `agent_directed` 只允许非破坏性的新增或预览动作；纠正、删除、库存处置、目标/偏好修改和维护操作继续要求各自的明确授权与句柄。
5. 把 `SKILL.md` 主干重写为“目标—观察点—能力地图—硬边界—结果合同”，详细领域规则继续按需放在 `references/`。
6. 工具描述只说明能力和输入输出，不把具体口语写成固定工作流。
7. 产品版本统一为 `0.7.5.0`，技术包版本升为 `0.9.1`；沿用 migration 022，不新增数据库迁移。

## 不可回归

CORE-01～CORE-10、SAFE-01～SAFE-07、GOV-01～GOV-02、UI-01 全部保持。Good Flags GF-001～GF-005 必须逐项通过：

- 普通餐食六项、每项双行；
- 纯水只显示饮水双行；
- “吃了个玉米”保留 `1个`、明确可食部估算；
- 紧接的明确纠正直接更新；
- v0.7.4.28 及已有候选目录保持不变。

本版不修改 WebUI、不新增业务功能、不重做营养计算、不改变过期食品过滤和相对时间语义。

## 验证

先写会在本地候选上失败的结构测试：普通正向输入不应获得具体工具提示或动作白名单；源码不应存在 `classifyDirectWrite`；Skill 不应包含封闭正向路线。

随后复测只读、否定、计划、他人、取消、重复失败、删除目标、复合写入、库存联动、相对时间、过期过滤、入库默认值和所有 Good Flags。能力测试评价最终数据库事实、工具结果和回执，不要求每个成功表达使用同一调用序列。

最后运行全部 Python、TypeScript、迁移、安装、升级、Skill、敏感信息和发布门禁。真实 OpenClaw UAT 记录轨迹用于发现失控，但不把一条成功轨迹固化为唯一合法路线。

## 回退

v0.7.5.0 仍使用 migration 022。若从已经迁移的 v0.7.5.0 回退到 v0.7.4.28，必须恢复升级前冷备份；若只在同一 v0.7.5.0 候选内回退代码，可继续使用同一 migration 022 数据库。
