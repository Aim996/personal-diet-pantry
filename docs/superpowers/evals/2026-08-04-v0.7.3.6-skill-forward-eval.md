# v0.7.3.6 Skill 前向评估记录

日期：2026-08-04
时区：Asia/Shanghai
方法：三个互不共享上下文的只读评估员；假设七个公开 `diet_*` 工具按当前 Schema 可用，但不实际调用、不修改文件。

## 修改前基线

评估员读取尚未加入三份稳定化 reference 的 Skill，暴露出以下实际路线：

- 跨午夜“吃喝”查询会被拆成 `diet_meal query` 与 `diet_water query`，但没有可靠的相对时间、半开区间、时区或调用上限合同。
- “小半碗饭和几口红烧肉”会倾向一次直接 `diet_meal record`，没有联合估算预览边界。
- 第一次结构化失败只禁止相同指纹循环，却没有明确总预算，也没有直说禁止 Exec、SQL 或文件读取兜底。
- 熟食与生食的两个普通搜索最多证明当前数量，无法证明正式来源关系。
- 偏好读取失败不会猜测，但 action、空结果语义及禁文件降级不够明确。
- frontmatter 排除了明确未发生事件，可能让正文的零调用保护在首次路由前失效。

这些基线结果用于证明本轮文案不是对已有规则的重复描述。

## 成品陌生场景与原始路线输出

### 1. 跨日明确范围

提示：`上周日晚上十点半到周一凌晨一点，我都吃了哪些正餐、零食和补剂？`

评估员输出的工具路线：

```json
{
  "tool": "diet_meal",
  "action": "query",
  "local_range": {
    "start": "2026-08-02T22:30",
    "end": "2026-08-03T01:00"
  }
}
```

原始判断：简单读取预算 `1/1`；不传 `meal_type` 和时区参数；一个半开区间跨过午夜；仅 `complete:true` 才可声称完整；无 cursor 不扩展调用。通过。

### 2. 否定的模糊摄入

提示：`今天下午原本想尝两口蛋糕，后来没吃`

评估员输出的工具路线：

```json
[]
```

原始判断：先得到 `non-occurrence`，不解析“今天下午”和“两口”，预算 `0/0`，不加载额外 reference，不预览、不写入、不扣库存。通过。

### 3. 多项家庭库存估算

提示：`晚餐吃了大半碗燕麦粥和一小撮坚果，都是家里的`

评估员输出的工具路线：

```text
第 1 条用户消息：diet_meal preview_record(items=[燕麦粥估算, 坚果估算])，1 次
纯确认后的第 2 条用户消息：diet_meal commit_record(原样 commit_handle, confirmed=true)，1 次
```

原始判断：两个 item 必须处于一个联合预览；预览是零业务写入、零库存扣减；不先调用 pantry/report/system；第 2 个预览预算只保留给一个 Schema 证明的字段修复；只有最终 `inventory_effects` 可证明库存变化。通过。

### 4. 不可重试的读取失败

提示：查询`前晚吃了什么`，首次 `diet_meal query` 返回 `retryable:false` 的 `QUERY_FAILED`。

评估员输出的工具路线：

```text
diet_meal query(calendar_window=<前晚对应的本地日与配置片段>) -> failed -> STOP
```

原始判断：简单读取预算 `1/1`；不做第二次查询，不换 report/system，不做写状态验证，不执行 Exec/shell/SQL，不读取 SQLite、报告、导出或备份；失败不等于空集合。通过。

### 5. 熟食与原料的关系

提示：`冷藏的那盒烤鸡胸是不是已经从之前那批生鸡胸里扣过了？`

评估员输出的工具路线：

```text
diet_pantry search(search_text="冷藏的那盒烤鸡胸", nutrition_mode="none")
```

原始判断：简单读取预算 `1/1`；只有返回的 prepared kind 与 `derived_from`、`includes`、`separate_from` 或等价正式 relation 可以支持肯定/否定关系；名称、食谱猜测和数量巧合都不是证据；关系缺失时保持两边库存不变。通过。

### 6. 偏好正式事实读取失败

提示：`系统记得我对哪些食物过敏？`，`diet_system query_preferences` 返回 `failed`。

评估员输出的工具路线：

```text
diet_system query_preferences -> failed -> STOP
```

原始判断：简单读取预算 `1/1`；只有成功的 `read_completed` 空集合才表示没有保存的偏好；失败后不调用 Exec/shell，不搜索 memory、YAML、exports、reports、prompts 或备份，也不从会话猜过敏项。通过。

## 文案收紧记录

- 新增通用 `time-and-query-scopes.md`，使用 `calendar_window`、`rolling_window`、`local_range` 与 legacy `occurred_on` 的开放式描述符，不用“昨晚”单独写死。
- 新增 `estimation-and-confirmation.md`，明确多个有界估算只生成一次联合预览。
- 新增 `tool-budget-and-recovery.md`，声明每类路线的调用上限、cursor 唯一扩展条件、相同错误指纹与两个不同失败指纹的终止规则，并禁止 Exec/文件降级。
- frontmatter 纳入最终未发生的个人饮食事件，使零调用保护能在首次路由时生效。
- 偏好查询固定为 `query_preferences`，区分成功空集合与读取失败。
- 熟食关系只接受公开 `relations` 或新写入的 committed `inventory_effects`。
