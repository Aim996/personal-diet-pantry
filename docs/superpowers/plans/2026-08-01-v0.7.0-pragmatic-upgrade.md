# 食序管家 v0.7.0 务实升级 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留现有核心饮食能力和 `0.6.1.5.1` 回退路径的前提下，用五个有界工作包交付一个可构建、可安装、可验证的 `0.7.0`。

**Architecture:** 不重写七领域工具与 Python 服务。先清理被中止的 TW4 测试草稿并恢复全套测试基线，再把现有真实场景测试组成一个不超过 25 条的核心快速门禁，最后统一升级版本、数据导入兼容范围和发布文档。已经通过的营养、幂等、自然口语、库存和体重实现只做验证，不为了产生代码改动而重写。

**Tech Stack:** Python 3.11–3.13、pytest、SQLite、TypeScript 5.9、Vitest、OpenClaw plugin、PowerShell CI、npm 可安装包。

## Global Constraints

- 正式目标版本精确为 `0.7.0`；不生成 partial/dev 版本。
- 可回退版本精确为 `0.6.1.5.1`（内部包版本 `0.6.2-dev.6`）。
- 保持七个顶层工具名：`diet_meal`、`diet_water`、`diet_weight`、`diet_pantry`、`diet_transaction`、`diet_report`、`diet_system`。
- 不要求保留 `0.6.1.5.1` 的全部 55 个动作；主动退化必须写入发布说明。
- SQLite 核心事实不得静默损坏；失败不得返回成功或生成重复业务记录。
- 每个工作包一次实现、一次相关回归；只有明确可复现的核心缺陷才能增加修复轮次。
- 不继续 Windows parent-handle 建目录、通用 AST writer scanner 或企业级跨进程安全证明。
- 当前生产实例、Docker、OpenClaw 和软路由不在本计划的写入范围。
- 发布前只在备份副本上演练升级；不读取或修改用户当前生产数据。
- Python 验证统一使用：

```powershell
$Python = 'C:\Users\example-user\Documents\Skill\.venv-task5\Scripts\python.exe'
```

- pytest 使用 `-p no:cacheprovider`，避免把缓存写入源码树。
- 任一计划内测试意外失败时停止当前工作包，用 `superpowers:systematic-debugging` 定位；不得绕过、静默 deselect 或继续下一包。
