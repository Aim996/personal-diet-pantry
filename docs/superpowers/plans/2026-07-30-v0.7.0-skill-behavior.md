# 食序管家 v0.7.0 SkillBehaviorContract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把散落在 Skill 主说明、references、TypeScript schema 和静态案例中的口语行为，收口为 contract v2、可生成动作目录、可重放 OpenClaw 工具轨迹、精确数据库差异和真实渠道验收共同组成的 `SkillBehaviorContract`。

**Architecture:** Python 服务不解析或猜测用户口语；OpenClaw 模型依据 Skill 和 references 形成 TurnPlan 并调用现有七个顶层工具。静态 case lint 只检查案例与文档结构，确定性 evaluator 只重放已经捕获或规范化的 OpenClaw 工具轨迹并验证真实 TypeBox、运行时、Python 服务和 SQLite 差异，WebUI/Telegram 验收单独证明“口语 → 工具”行为。

**Tech Stack:** OpenClaw tool plugin、TypeScript 5.9、TypeBox 1.1、Node.js 22.22.3+、Python 3.11–3.13、PyYAML、jsonschema 4.x、SQLite、pytest、Vitest、PowerShell CI。

## Global Constraints

- 目标版本固定为 `0.7.0`，当前兼容基线为 `0.6.7`。
- 保留 `diet_meal`、`diet_water`、`diet_weight`、`diet_pantry`、`diet_transaction`、`diet_report`、`diet_system` 七个顶层工具名。
- Python 不得新增自然语言分类器、分句器、正则路由器或裸数字意图猜测器。
- SQLite 正式表仍是事实源；prompt、Skill 文本、golden trace 和 metric snapshot 都不是业务事实源。
- `contracts/tools.yaml` contract v2 是 action、handler、policy、公开字段、handle route、reference vocabulary 和行为 tag 的单一契约源。
- 静态 lint 不得再输出或宣传“行为通过率”；真实 replay 与真实渠道成绩必须分开报告。
- 否定按事件绑定；纠错优先更新上一条可修改事实；跨域多意图按依赖顺序执行且不得伪装为跨域原子事务。
- purchase、possession、stocked 是不同事实；只有 stocked 创建或链接家庭库存批次。
- consumption location 与 item-level inventory provenance 是不同字段。
- 安全案例通过率必须为 `100%`；无效 action、无效 payload、禁止调用、重复写入、漏事件和跨会话 handle 消费必须均为 `0`。
- 确定性行为案例不得少于 `50` 个，本计划固定为 `59` 个。
- FoodDecision FD1 是 `migrations/020_recipe_shopping_lifecycle.sql` 的唯一
  schema owner；FD1 一次写入 shopping、meal provenance 和 preparation-loss
  最终结构。SB4 只消费并验证 migration 020，不再追加或改写已验证的迁移。
- SB4 与 FoodDecision 对 `src/schemas.ts` 的修改必须串行，执行者不得同时
  编辑这个共享文件。
- FoodDecision 负责登记并实现 `mark_shopping_item_purchased`、`stock_shopping_item`、`cancel_shopping_item`；本计划消费这些正式 action，不另建同义 action。
- 不新增 022 迁移；cooking/provenance 表结构由 FD1 一次并入 migration 020。
- 不全面重写 `service.py`，只增加输入适配和调用既有领域函数所需的最小改动。
- IntegrationRelease IR6 owns the one clean candidate `.tgz` and
  installer-produced runtime receipt. SB8 consumes those exact bytes and proves
  the running plugin identity matches; it must not silently rebuild or
  substitute another candidate.
- The only formal live-validator/CI interface is candidate archive + manifest +
  explicit raw-evidence root + external run ledger. The installed plugin keeps
  its installer-created receipt at `runtime/install-receipt.json`; its formal
  evidence copy is accepted only as the same indexed relative member below the
  raw root. There is no `--runtime-install-receipt` or
  `-SkillAcceptanceRuntimeInstallReceipt` parameter in capture, validation, CI,
  audit or IR6 handoff.
- Live channel/session classification is evidence, not an operator label:
  trusted Gateway/runtime metadata is outside model-controlled action arguments,
  and every sanitized label is independently derived and hash-bound.

## File Structure

### Contract 与生成

- `contracts/tools.yaml`：contract v2 唯一人工维护源。
- `scripts/generate_tool_contracts.py`：加载、验证 contract v2 并生成所有运行时、Skill 和文档产物。
- `contracts/public-behavior.yaml`：生成的公开动作与行为 policy。
- `contracts/behavior-action-index.yaml`：生成的 action → behavior tags/test references 索引。
- `src/generated/tool-contracts.ts`：不依赖 schema 的工具名、动作、公开字段、action runtime policy、handle route 和 reference enum 常量。
- `src/generated/tool-schemas.ts`：导入真实 TypeBox schema，并生成七域 schema object 映射。
- `python/personal_diet_pantry/generated_tool_contracts.py`：Python action、handler 和 policy 映射。
- `skills/personal-diet-pantry/references/generated-action-catalog.md`：随 Skill 打包的轻量动作与 canonical vocabulary 目录。
- `docs/GENERATED-ACTIONS.zh-CN.md`：完整开发者动作表。

### 运行时行为

- `src/index.ts`：七个 OpenClaw 工具的兼容编排入口。
- `src/reliability.ts`：从生成 action runtime policy 判定正式 mutation，不再维护手写 `FORMAL_MUTATIONS`。
- `src/runtime-tool.ts`：真实 schema 校验、payload normalization、运行时身份和 replay 共用 seam。
- `src/response.ts`：动作级公开响应过滤及进程内、会话级 workflow handle registry。
- `src/schemas.ts`：从生成 vocabulary 消费 canonical enum，并补齐 cooking/provenance 输入。
- `python/personal_diet_pantry/meals.py`：cooking、零消费、制作损耗、消费地点和库存来源的正式领域行为。
- `python/personal_diet_pantry/service.py`：新字段到领域对象的输入适配。
- `python/personal_diet_pantry/waste.py`：把明确 preparation loss 纳入正式浪费查询，且不重复扣库存。
- `migrations/020_recipe_shopping_lifecycle.sql`：由 FD1 独占维护；SB4
  消费其中的购物状态机、meal provenance 和 preparation-loss 正式事实。

`collectActionBranchRecords` must return one record per real TypeBox union
branch, without collapsing to a `Set`:

```ts
type ActionBranchRecord = {
  branchIndex: number;
  actionPropertyCount: number;
  literalValues: readonly string[];
  hasUnconstrainedAction: boolean;
};
```

It walks only each branch's top-level `properties.action` definition and records
missing, repeated, multi-literal and unconstrained discriminators rather than
silently dropping them. The test compares the schema and contract domain sets
first, validates exactly one string literal discriminator per branch, rejects
duplicates on either side, and finally compares the sorted action arrays as a
multiset-preserving equality. A `Set` must never be the equality oracle.

The `meal.record` list above shows every top-level safe semantic leaf and the
first ingredient level. Because the real TypeBox schema supports bounded
recursive ingredients, implementation must materialize the same ingredient
semantic-leaf template at every concrete depth through
`MAX_INGREDIENT_LEVELS`; neither `...`, `**`, a subtree wildcard nor a shortened
example is valid in the checked-in contract. The independent registry and
TypeBox walker below determine the final exact list. Core quantity, nutrition,
inventory, ingredient and leftover leaves may never be moved to
`excludedFields` merely to make parity pass.

For `meal.record`, the independent registry must also classify every remaining
real TypeBox leaf at every ingredient depth. The only permitted exclusions are
`intent` as a fixed compatibility discriminator; `source_text`,
`items.*.raw_name`, `items.*.portion_expression` and their nested equivalents
as private free text; and `source_confidence`, `name_match_confidence`,
`quantity_confidence`, `batch_uniqueness`, `context_consistency`,
`personal_rule_confidence` plus those same six leaves below
`confidence_signals` as non-business telemetry. The registry materializes each
excluded path explicitly at all eight concrete ingredient depths; it contains
no subtree wildcard. In particular,
`nutrition_facts.source`, `nutrition_facts.uncertainty`,
`nutrition_estimate.source`, and `nutrition_estimate.uncertainty` remain
