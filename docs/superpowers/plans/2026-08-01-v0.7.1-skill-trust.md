# 食序管家 v0.7.1 Skill 可信记录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以可复制 Skill 为核心，修复模糊库存、补充信息误确认、做饭修正残留、缺失重量/用油/加工损耗和回复算术错误；同时保持 v0.7.0 的日常饮食能力，并在同等正确结果下减少 reference 读取、预查询和重复工具调用。

**Architecture:** `SKILL.md` 作为稳定导航和跨领域不变量前缀，最小充分 references 定义专项写入准备度；同轮读取结果和不透明句柄只复用、不重查。真实中文场景评测保护模型行为。Python/TypeScript 只增加两类无法由提示词保证的通用保护：库存匹配优先验证用户原名；做饭修正以一个事务替换旧餐、原料扣减和派生剩菜。现有七个顶层工具名不变，不增加部署环境逻辑或 DeepSeek 专属调用代码。

**Tech Stack:** Markdown Agent Skill、YAML 行为夹具、Python 3.12、pytest、SQLite、TypeScript 5.9、TypeBox、Vitest、OpenClaw plugin、PowerShell CI。

## Global Constraints

- 正式目标版本精确为 `0.7.1`；不生成 partial、dev 或“部分功能”版本。
- 基线和直接回退版本为 `0.7.0`。
- 产品中心是 `skills/personal-diet-pantry/`；工具实现只承担必要数据不变量。
- 保持七个顶层工具名：`diet_meal`、`diet_water`、`diet_weight`、`diet_pantry`、`diet_transaction`、`diet_report`、`diet_system`。
- 不加入 OpenClaw、Telegram、Docker、Lucky、WireGuard、软路由、IP、令牌或用户 ID 专属逻辑。
- 不读取、修改或部署用户当前生产实例和生产数据库。
- Skill 修改必须先有失败的文本/路由评测；生产代码修改必须先有失败的回归测试。
- 不把硬歧义变成低置信度估算；缺少一个关键事实时只问一个问题并保持零写入。
- 不用重复提示词或填充文本追求 DeepSeek 缓存；只稳定必要前缀，并把动态会话事实留在宿主请求后部。
- 普通单领域消息只读取一个 reference；真正跨领域最多两个，同一轮不得重复读取同一文件。
- 明确且完整的单领域事件只执行一次正式工具动作；读取仅用于目标歧义、既有状态定位、聚合查询或完整性保护。

```python
def resolve_meal_inventory_name(
```

```python
def prepare_cooking_for_commit(
    connection: sqlite3.Connection,
    draft: CookingDraft,
    settings: Settings,
    *,
    replacing_meal_id: int | None = None,
) -> _PreparedMeal:
    if not isinstance(draft, CookingDraft):
        raise MealValidationError("draft must be a CookingDraft")
    consumed = _positive_cooking_quantity(
        draft.consumed_quantity, "consumed_quantity"
    )
    unit = _required_text(draft.unit, "unit")
    leftover_quantity = Decimal("0")
    if draft.leftover is not None:
        if draft.leftover.unit.strip().lower().rstrip("s") != unit.lower().rstrip("s"):
            raise MealValidationError("consumed and leftover dish units must match")
        leftover_quantity = _positive_cooking_quantity(
            draft.leftover.quantity, "leftover quantity"
        )
    prepared_quantity = consumed + leftover_quantity
    meal_draft = MealDraft(
        intent="record",
        occurred_at=draft.occurred_at,
        meal_type=draft.meal_type,
        source_text=draft.source_text,
        location_type="home",
        items=(MealItemDraft(
            raw_name=draft.dish_name,
            normalized_name=draft.normalized_name,
            amount=consumed,
            unit=unit,
            ingredients=tuple(draft.ingredients),
            leftover=draft.leftover,
        ),),
        nutrition_repository=draft.nutrition_repository,
    )
    credits = (
        _meal_inventory_credits(connection, replacing_meal_id)
        if replacing_meal_id is not None
        else {}
    )
    whole_recipe = _prepare_meal(
        connection, meal_draft, settings, inventory_credits=credits
    )
    for item in whole_recipe.items:
        if item.public.role is MealItemRole.INGREDIENT and (
            item.public.inventory_action is not InventoryLinkAction.DEDUCT
        ):
            raise InsufficientStockError(
                f"INSUFFICIENT_STOCK: insufficient eligible stock for {item.public.normalized_name}"
            )
    return _scale_prepared_meal(
        whole_recipe, consumed / prepared_quantity
    )
```

当 `replacing_meal_id` 存在时，把 `_meal_inventory_credits(connection, id)` 传给 `_prepare_meal`，使旧原料在同一修正中可恢复再选择。`record_cooking` 改为调用该函数，保持现有公开行为不变。

- [ ] **Step 4: 在同一事务退役旧剩菜**

在 `_detach_meal_inventory` 开头调用新 helper：

```python
def _retire_derived_leftovers(
    connection: sqlite3.Connection,
    context: MutationContext,
    meal_id: int,
    *,
    changed_at: str,
    reason: str,
) -> None:
    rows = connection.execute(
        "SELECT * FROM pantry_batches WHERE source_meal_id = ? ORDER BY id",
        (meal_id,),
    ).fetchall()
    for row in rows:
        movements = connection.execute(
            "SELECT movement_type FROM pantry_movements "
            "WHERE pantry_batch_id = ? ORDER BY id",
            (row["id"],),
        ).fetchall()
        untouched = (
            Decimal(str(row["remaining_quantity"]))
            == Decimal(str(row["initial_quantity"]))
            and [movement["movement_type"] for movement in movements] == ["add"]
        )
        if not untouched:
            raise PreviewStaleError(
                "Cannot safely correct cooking after derived leftovers changed"
            )
        quantity = Decimal(str(row["remaining_quantity"]))
        context.update(
            "pantry_batches",
            row["id"],
            {
                "remaining_quantity": 0,
                "status": "consumed",
                "version": int(row["version"]) + 1,
            },
        )
        context.insert(
            "pantry_movements",
            {
                "pantry_batch_id": row["id"],
                "movement_type": "adjust",
                "quantity": _sqlite_real(quantity, "leftover correction"),
                "unit": row["unit"],
                "reason": reason,
                "linked_meal_id": meal_id,
                "linked_meal_item_id": None,
                "prior_status": row["status"],
                "created_at": changed_at,
            },
        )
```

对每个 `source_meal_id = meal_id` 的批次，只有 `remaining_quantity == initial_quantity` 且创建后的 movement 只有原始 `add` 时才允许修正。允许时用同一 `MutationContext` 把 `remaining_quantity` 置0、`status` 置 `consumed`、`version + 1`，并写一条 `adjust` movement，reason 明确为 correction。任何后续消费、丢弃或绝对调整都先抛 `PreviewStaleError`，不得发生部分更新。

```python
def _apply_preparation_losses(
    result: NutritionResult,
    losses: tuple[PreparationLossDraft, ...],
) -> NutritionResult:
    updates: dict[str, Decimal | None] = {}
    for field in (
        "calories", "protein", "fat", "carbohydrate",
        "fiber", "sodium", "hydration_ml",
    ):
        current = getattr(result, field)
        deduction = sum(
            (getattr(loss.nutrition_facts, field) or Decimal("0"))
            for loss in losses
        )
        if current is None:
            if deduction > 0:
                raise MealValidationError(
                    f"cannot subtract known preparation loss from unknown {field}"
                )
            updates[field] = None
            continue
        remaining = current - deduction
        if remaining < 0:
            raise MealValidationError(
                f"preparation loss exceeds consumed {field}"
            )
        updates[field] = remaining
    return replace(result, **updates)
```
