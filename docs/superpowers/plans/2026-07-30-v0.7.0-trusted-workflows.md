# 食序管家 v0.7.0 Trusted Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 `TrustedWorkflowModule`，修复删除残留和锁外 digest、空效果撤销、维护中断锁死、历史备份无法恢复、凭据字段漏脱敏、源码归档扫描盲区及 self-check schema 盲区。

**Architecture:** `migrations/019_trusted_workflows.sql` 为事务增加明确的 undo policy、effect count 和 opaque workflow lineage；`control-migrations/002_maintenance_evidence.sql` 保存维护阶段的 expected/observed 证据与 reconciliation 判定。`TrustedWorkflowModule` 在 `service.py` 与现有 deletion/import/backup/maintenance implementation 之间形成唯一 seam，对外只暴露 `preview()`、`commit()`、`recover_startup()` 和 `inspect()`；业务 SQLite、控制 SQLite 和受管文件系统的复杂性全部留在 module implementation 内。

**Tech Stack:** Python 3.11–3.13、SQLite JSON1、pytest 8、TypeScript 5.9、TypeBox、Vitest 3。

## Global Constraints

- 七个顶层工具名称保持不变；本计划只给 `diet_system` 增加 `list_backups` 和 `preview_restore`。
- 不重写餐食、饮水、体重和库存旧核心，不把新的可信规则继续堆入 `service.py`。
- 不可逆 commit 必须先取得 `BEGIN IMMEDIATE` 写锁，再重建 plan、比较 digest、执行删除和 residue verification。
- `undo_policy = none`、空 snapshot、`effect_count = 0` 或已被隐私清理的事务不能进入 undo/redo 候选。
- import 和 privacy deletion 永远使用 `undo_policy = none`。
- `all_business` residue verifier 必须覆盖正式业务表、preview JSON、transaction snapshot/source、portable handles、派生 SQLite 数据以及 `cache/exports/reports` 文件。
- all-business quarantine 的 item identity 固定为
  `sha256(domain + NUL + normalized_relative_path)`；内容 SHA 只用于校验，不能作为
  item identity。物理 purge 必须先持久化 `purge_pending` 意图。
- all-business 删除在业务数据库 commit 前必须进行第二次 derived-root 扫描；commit
  后必须记录 `cache/exports/reports` 零文件 expected/observed evidence，不能只验证
  SQLite residue。
- `privacy_erasure_tombstones.control_operation_handle` 是 control operation 与业务
  tombstone 的唯一稳定绑定；所有 v0.7.0 新写入 tombstone 都必须带该值，恢复不得以
  “存在任意 tombstone”、时间邻近、scope 或 public `erasure_handle` 猜测归属。
- `cache/exports/reports` 的所有当前和未来发布者必须共用同一个跨进程 shared writer
  lease；all-business 删除在第一次枚举前取得 exclusive writer lease，并一直持有到
  residue evidence、物理 purge 与成功/失败 terminal evidence 全部持久化。启动恢复在
  任何文件检查或变更前重新取得同一 exclusive lease。同一 canonical lock path 的
  shared lease 以 owner token 进程内可重入：writer 已排队时同 owner nested call
  不阻塞，任何新 owner 必须等待。
- 每个 quarantine operation 必须先对其全部 manifest items 完成只读 preflight；
  任一 item 路径、hash、state、存在性或 matching tombstone 不确定时，该 operation
  整体进入 `verification_required`，在此之前不得移动、删除文件或推进任何 item state。
- quarantine 目录创建、文件 flush/replace/unlink、空目录删除全部走可验证的 durable
  primitives；任一 file/directory flush 失败都 fail closed，不得记录伪成功或
  `purged`。
- 删除不删除备份，回执必须明确 `backups_deleted = false`。
- 历史备份列表和恢复预览只返回 opaque backup id 与安全元数据，不返回文件名或绝对路径。
- restore 只消费 `preview_restore` 为具体备份生成的未过期 `commit_handle`。
- restore/import/delete/migrate 中断后不得自动重放；证据不足时以 `verification_required` 失败终止并释放 exclusive slot。
- maintenance artifact/check 必须分别保存 expected/observed evidence，并按 operation、stage 和 evidence key 唯一。
- credential key 命中后从 mapping 中直接删除，不把字段保留为 `[REDACTED]`；普通字符串中的 secret-like 片段仍替换为 `[redacted]`。
- source archive 敏感扫描必须读取实际归档成员字节；不得整体排除 `tests` 或 `src-tests`。
- self-check expected tables、indexes 和 foreign keys 必须从正式 migration 链生成，不维护手写 `_EXPECTED_TABLES/_EXPECTED_INDEXES`。
- TW6 是 SkillBehavior Task SB1 的硬前置：TW6 必须在当前 contract v1 上完成两个 system action、运行当前 v1 生成器并提交；SB1 随后负责迁移到 contract v2 和扩大全量生成物。TW6 不得创建或声称 contract v2。

Add transaction policy and conservative backfill:

```sql
ALTER TABLE transactions
ADD COLUMN undo_policy TEXT NOT NULL DEFAULT 'snapshot'
CHECK (undo_policy IN ('snapshot', 'none'));

ALTER TABLE transactions
ADD COLUMN effect_count INTEGER NOT NULL DEFAULT 0
CHECK (typeof(effect_count) = 'integer' AND effect_count >= 0);

UPDATE transactions
SET effect_count = MAX(
    COALESCE(json_array_length(before_snapshot), 0),
    COALESCE(json_array_length(after_snapshot), 0)
);

UPDATE transactions
SET undo_policy = 'none',
    effect_count = 0
WHERE effect_count = 0;

UPDATE transactions
SET undo_policy = 'none'
WHERE id IN (
    SELECT transaction_id
    FROM operation_previews
    WHERE operation_type = 'import_preview'
      AND transaction_id IS NOT NULL
);

UPDATE transactions
SET undo_policy = 'none'
WHERE status IN ('committed', 'reverted')
  AND EXISTS (
      SELECT 1
      FROM operation_previews AS preview
      JOIN privacy_erasure_tombstones AS tombstone
        ON tombstone.preview_token_hash = preview.token_hash
      WHERE preview.operation_type = 'delete_data_preview'
        AND preview.consumed_at IS NOT NULL
  );
```

The import backfill must use the stable `import_preview` operation type and its transaction foreign key; it must not inspect `source_text` or transaction-ID prefixes. Migration 018 does not retain per-transaction targets for a committed privacy erasure, so the stable consumed `delete_data_preview` plus tombstone marker requires a conservative backfill of every pre-019 committed/reverted transaction. The import/privacy policy updates change only `undo_policy`; a non-zero `effect_count` remains non-zero audit evidence and never makes those operations undoable.

Add the stable cross-database operation binding without inventing a foreign key between
the business and control SQLite files:

```sql
ALTER TABLE privacy_erasure_tombstones
ADD COLUMN control_operation_handle TEXT
CHECK (
    control_operation_handle IS NULL
    OR (
        length(control_operation_handle) = 36
        AND substr(control_operation_handle, 1, 4) = 'mop_'
        AND substr(control_operation_handle, 5)
            NOT GLOB '*[^0-9a-f]*'
    )
);

CREATE UNIQUE INDEX
idx_privacy_erasure_tombstones_control_operation
ON privacy_erasure_tombstones(control_operation_handle)
WHERE control_operation_handle IS NOT NULL;
```

Migration 019 leaves pre-existing tombstones `NULL` because their control operation
cannot be reconstructed safely. Application code after 019 must never create another
`NULL`: `TrustedWorkflowModule` passes the accepted `operation.handle` through
`data_erasure.commit_plan()` to the tombstone insert in the same business transaction.
The partial unique index is the database-enforced one-operation-to-at-most-one-tombstone
constraint; recovery treats legacy `NULL` tombstones as unrelated evidence.

```python
class TrustedWorkflowModule:
    def __init__(self, dependencies: TrustedWorkflowDependencies) -> None:
        self._dependencies = dependencies

    def preview(
        self,
        command: WorkflowCommand,
        request_context: RequestContext,
    ) -> WorkflowPreview:
        del command, request_context
        raise ValueError("trusted workflow preview is unsupported")

    def commit(
        self,
        workflow_handle: str,
        confirmation: Confirmation,
    ) -> OperationReceipt:
        del workflow_handle, confirmation
        raise ValueError("trusted workflow commit is unsupported")

    def recover_startup(self) -> RecoveryReport:
        return RecoveryReport(
            inspected=0,
            committed=0,
            failed=0,
            verification_required=0,
        )

    def inspect(self, query: TrustQuery) -> TrustReport:
        if not isinstance(query, SelfCheckQuery):
            raise ValueError("trusted workflow inspection is unsupported")
        checks = self_check.run_self_check(
            self._dependencies.connection(),
            self._dependencies.data_paths,
            self._dependencies.migrations_dir,
            source_root=self._dependencies.source_root,
            now=query.now,
        )
        control_checks = self._dependencies.controller.validate()
        return TrustReport(
            kind="self_check",
            payload={"checks": (*checks, *control_checks)},
        )
```

```python
from __future__ import annotations

from dataclasses import dataclass
import json
import sqlite3
from typing import Iterable


@dataclass(frozen=True)
class EntityLink:
    entity_kind: str
    entity_key: str
    relation: str


def _entries(snapshot: str, relation: str) -> tuple[EntityLink, ...]:
    parsed = json.loads(snapshot)
    if not isinstance(parsed, list):
        raise ValueError("transaction snapshot must be an array")
    links: list[EntityLink] = []
    for entry in parsed:
        if not isinstance(entry, dict):
            continue
        table = entry.get("table")
        row_id = entry.get("row_id")
        if isinstance(table, str) and row_id is not None:
            links.append(EntityLink(table, str(row_id), relation))
    return tuple(links)


def _insert_links(
    connection: sqlite3.Connection,
    *,
    workflow_kind: str,
    workflow_key: str,
    links: Iterable[EntityLink],
    created_at: str,
) -> None:
    connection.executemany(
        """
        INSERT OR IGNORE INTO workflow_entity_links (
            workflow_kind, workflow_key, entity_kind, entity_key,
            relation, created_at
        ) VALUES (?, ?, ?, ?, ?, ?)
        """,
        (
            (
                workflow_kind,
                workflow_key,
                link.entity_kind,
                link.entity_key,
                link.relation,
                created_at,
            )
            for link in links
        ),
    )


def index_transaction_snapshots(
    connection: sqlite3.Connection,
    *,
    transaction_id: str,
    before_snapshot: str,
    after_snapshot: str,
    created_at: str,
) -> None:
    _insert_links(
        connection,
        workflow_kind="transaction",
        workflow_key=transaction_id,
        links=(
            *_entries(before_snapshot, "before"),
            *_entries(after_snapshot, "after"),
        ),
        created_at=created_at,
    )


def index_preview_links(
    connection: sqlite3.Connection,
    *,
    token_hash: str,
    links: Iterable[EntityLink],
    created_at: str,
) -> None:
    _insert_links(
        connection,
        workflow_kind="preview",
        workflow_key=token_hash,
        links=links,
        created_at=created_at,
    )


def workflow_keys_for_entities(
    connection: sqlite3.Connection,
    entities: Iterable[tuple[str, str]],
) -> tuple[tuple[str, str], ...]:
    found: set[tuple[str, str]] = set()
    for entity_kind, entity_key in entities:
```

Canonicalize the validated lock path once as an absolute, normalized,
platform-case-normalized path without traversing a symlink/reparse point. A
module-global registry keyed by that canonical path returns one
`_ProcessLeaseState` for every manager instance in the process; it owns the mutex,
condition, active-owner depths, waiting-writer count and OS handles. A per-instance gate
is forbidden because `self_check`, reports and service code may construct different
manager objects for the same lock file.

`LeaseOwnerToken` is issued only by the first successful shared acquisition and contains
the canonical-path identity, current PID and an unguessable owner nonce. A supplied token
is accepted only when the same `_ProcessLeaseState` still records that exact active
owner; cross-process, cross-path, forged or stale tokens fail closed. Shared semantics
are:

1. first acquisition for a new owner waits while an exclusive owner is active **or any
   exclusive waiter is queued**, then acquires one OS shared lock handle and records
   `depth=1`;
2. re-entry with the same active owner increments its depth immediately, reuses the same
   OS handle and never waits behind a queued exclusive writer;
3. exit decrements depth; only the outermost exit releases the OS handle and wakes the
   queued writer;
4. a different/new owner remains blocked once an exclusive waiter is queued. Shared to
   exclusive upgrade by an active owner is rejected instead of self-deadlocking.

`exclusive_erasure()` increments `waiting_writers` while holding the process-state
mutex **before** waiting for all active owner depths to reach zero. It then acquires the
OS exclusive lock, marks exclusive active and decrements the waiter count. Release
clears exclusive active and wakes waiters. Failure at any stage restores counters under
the same mutex, so a failed acquire cannot leave new owners permanently blocked.

POSIX uses `fcntl.flock(fd, LOCK_SH/LOCK_EX)`; Windows uses `LockFileEx` through
`ctypes` with shared mode for publishers and `LOCKFILE_EXCLUSIVE_LOCK` for erasure.
Acquisition and release errors are hard failures.

`data_export.export_data()` and ordinary report entry points acquire a new shared owner
**before** their first business-fact read and release only after final atomic write and
parent-directory flush. `self_check.run_self_check(write_report=True)` acquires one
outer owner before any checks, passes that exact token through all nested
daily/weekly/monthly report builders and its health-report writer, and releases only
after the last durable publish. Each nested publisher calls
`shared_publisher(owner=outer_owner)` and therefore reuses the outer OS lock; it must not
silently create a new owner. A future cache publisher follows the same helper. Locking
only inside `atomic_write_text()` is too late and fails the ordering tests.

`TrustedWorkflowModule._commit_delete()` acquires in this fixed order:
maintenance exclusive slot → derived-file exclusive lease → business
`BEGIN IMMEDIATE`. It holds the derived lease from before the first root enumeration
through manifest, all moves, second scan, business commit/tombstone, third scan,
expected/observed evidence, purge, terminal evidence and return. Error restoration and
failure evidence also occur before release. After a process crash the OS releases the
file lock; `_reconcile_erasure_quarantines()` must reacquire exclusive before its
read-only preflight and retain it through reconciliation terminal evidence.

The protocol is exact:

- validate every component as owned and reject symlink/reparse traversal before opening;
- POSIX regular files use `os.open(..., O_RDONLY | O_NOFOLLOW)` + `os.fsync()` and
  directories use `O_RDONLY | O_DIRECTORY | O_NOFOLLOW` + `os.fsync()`;
- Windows regular files use `CreateFileW` without reparse following plus
  `FlushFileBuffers`; directories additionally use `FILE_FLAG_BACKUP_SEMANTICS`;
- `durable_mkdir()` creates one missing component at a time, flushes the new directory,
  then its already-durable parent before proceeding;
- `durable_replace()` requires regular files on the same volume, flushes source bytes,
  calls `os.replace()`, reopens and flushes destination bytes, then flushes source and
  destination parents (once if identical);
- `durable_unlink()` is called only after committed `purge_pending`, flushes the target
  file, unlinks it, then flushes the parent;
- `durable_rmdir()` verifies the owned quarantine directory is empty, flushes that
  directory, removes it and flushes its parent.

任何 open/validation/flush/close 失败都使当前 operation 失败或进入
`verification_required`；不能把任何一步降级为静默 best effort，也不能在失败后
记录 success、`purged` 或删除 manifest evidence。

| absent | `planned` | 1/0 | original hash 相等，标记 `restored`；说明 move 未发生 |
| absent | `planned` | 0/1 | staged hash 相等，durable restore，标记 `restored` |
| absent | `staged` | 0/1 | durable restore，标记 `restored` |
| absent | `staged` | 1/0 | original hash 相等，标记 `restored`；说明 restore 已发生但状态未落库 |
| absent | `restored` | 1/0 | hash 相等，保持 terminal |
| committed | `staged` | 0/1 | 写 `purge_pending`，durable unlink，写 `purged` |
| committed | `purge_pending` | 0/1 | hash 相等，完成 unlink，写 `purged` |
| committed | `purge_pending` | 0/0 | 直接写 `purged`；durable unlink 已完成，pending 是持久意图 |
| committed | `purged` | 0/0 | 保持 terminal |

其他组合全部 `verification_required` 且不移动文件，包括：任意 1/1、absent
tombstone 下 0/0、committed tombstone 下 original 存在、没有 committed tombstone

```python
@dataclass(frozen=True)
class ExpectedSchema:
    tables: frozenset[str]
    indexes: frozenset[str]
    foreign_keys: Mapping[
        str,
        tuple[tuple[str, str, str, str], ...],
    ]


def _schema_snapshot(connection: sqlite3.Connection) -> ExpectedSchema:
    tables = frozenset(
        str(row[0])
        for row in connection.execute(
            """
            SELECT name
            FROM sqlite_master
            WHERE type = 'table'
              AND name NOT LIKE 'sqlite_%'
            """
        )
    )
    indexes = frozenset(
        str(row[0])
        for row in connection.execute(
            """
            SELECT name
            FROM sqlite_master
            WHERE type = 'index'
              AND name NOT LIKE 'sqlite_%'
            """
        )
    )
    foreign_keys = {
        table: tuple(
            sorted(
                (
                    str(row["from"]),
                    str(row["table"]),
                    str(row["to"]),
                    str(row["on_delete"]),
                )
                for row in connection.execute(
                    f"PRAGMA foreign_key_list({table})"
                )
            )
        )
        for table in sorted(tables)
    }
    return ExpectedSchema(tables, indexes, foreign_keys)


def _expected_schema(migrations_dir: Path) -> ExpectedSchema:
    expected = sqlite3.connect(":memory:")
    expected.row_factory = sqlite3.Row
    expected.execute("PRAGMA foreign_keys = ON")
    try:
        apply_migrations(expected, Path(migrations_dir))
        return _schema_snapshot(expected)
    finally:
        expected.close()
```

Import `dataclass`, `Mapping` and `apply_migrations`. Delete `_EXPECTED_TABLES` and `_EXPECTED_INDEXES`.
