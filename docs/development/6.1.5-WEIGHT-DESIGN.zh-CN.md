# 食序管家 6.1.5 体重记录设计

状态：已确认  
用户版本：6.1.5  
安装包版本：`0.6.2-dev.5`
基线：`0.6.1`（提交 `74ca5ba14584076b292da234e73a5d82297b5e18`）

## 1. 目标

新增一个简单、独立、可撤销的体重时间序列：

- 用户发送明确体重或单独发送裸数字时，直接记录；
- 测量时间只取服务端系统当前时间，不接受模型或用户传入时间；
- 可选保存自由文本状态，例如“空腹”“睡前”“运动后”；
- 写入后返回最近 7 日均值；
- 当前 7 日窗口和前一 7 日窗口都有数据时，返回上升、下降或持平信号。

当前 Skill 对“105”“105 空腹”“记录体重105”“我105kg，睡前”均无法写入，
基线测试会要求补充或提示不支持。本版本必须让这些表达进入同一个确定性体重流程。

## 2. 领域边界

新增第七个公共工具 `diet_weight`，不把体重塞进饮水、报告或系统配置。

`diet_weight` 提供四个动作：

| 动作 | 作用 |
| --- | --- |
| `record` | 按系统时间写入一条体重 |
| `query` | 返回最近记录、7 日均值和趋势 |
| `update` | 通过短期工作流句柄修改体重或状态 |
| `delete` | 通过短期工作流句柄逻辑删除记录 |

公共工具数从 6 增至 7，公共动作数从 51 增至 55。体重写入、修改和删除进入现有
事务日志，因此可以通过 `diet_transaction` 撤销和重做。

## 3. 输入规则

### 3.1 体重

- 裸数字默认单位为 `kg`；
- 当消息是单独的正数或“正数 + 状态”且没有其他领域对象、待处理确认或修改句柄时，
  将其路由为体重；其他明确领域意图仍按原有优先级处理；
- 显式支持 `kg`、`斤` 和 `lb`；
- 持久化前统一换算为整数克，避免二进制浮点误差；
- 拒绝非有限值、非正数和明显超出边界的值；
- 对用户的明确已测量表达直接写入，不走预览确认。

### 3.2 时间

`measured_at` 不出现在公共工具参数中。服务端使用本次操作的可信系统时钟并以 UTC
保存；返回时按配置的 `Asia/Shanghai` 等用户时区呈现。修改记录时保留原始测量时间，
删除时间也由服务端生成。

### 3.3 状态

状态字段为可选自由文本 `status_note`：

- 示例：“空腹”“睡前”“运动后”“晚饭后”；
- 不使用固定枚举，不擅自归类；
- 未提供时保存为 `NULL`；
- 去除首尾空白，限制为最多 80 个字符；
- 更新时允许显式清空。

## 4. 数据模型

迁移 `015_body_weight_logs.sql` 新增 `body_weight_logs`：

| 字段 | 语义 |
| --- | --- |
| `id` | 内部主键，不直接暴露给模型 |
| `measured_at` | 服务端系统测量时间，UTC |
| `weight_g` | 统一后的整数克 |
| `status_note` | 可选自由状态 |
| `version` | 每次修改递增的内部资源版本，防止旧句柄重复修改 |
| `created_at` / `updated_at` | 审计时间 |
| `deleted_at` | 逻辑删除时间 |
| `transaction_id` | 事务证据 |

为活动记录建立按 `measured_at` 查询的索引。备份仍是完整 SQLite 快照，无需增加第二
份数据文件。

## 5. 7 日均值与趋势

以服务端当前时间 `now` 为锚点：

- 当前窗口：`(now - 7 days, now]`；
- 对照窗口：`(now - 14 days, now - 7 days]`；
- 每条活动记录等权；
- 平均值和差值对外保留一位小数，使用十进制四舍五入。

返回规则：

- 当前窗口有数据：返回 `seven_day_average_kg`；
- 两个窗口都有数据：返回 `trend`；
- 当前均值更低：`direction = down`；
- 当前均值更高：`direction = up`；
- 差值显示为 `0.0 kg`：`direction = stable`；
- 对照窗口没有数据：完全省略趋势，不返回伪造的零变化。

Skill 的正常回复形状：

```text
已记录体重：105 kg｜空腹
记录时间：2026年7月30日 08:30
7日均值：104.8 kg
趋势：7日均下降 ⬇️0.5 kg
```

若没有状态、当前均值或可比较趋势，对应行直接省略。正常回复不出现数据库 ID、事务
ID、句柄或工具名称。

## 6. 可靠性与兼容

- `record`、`update`、`delete` 都是正式写入，复用现有操作回执和不确定提交恢复；
- 修改、删除只接受短期 `record_handle`，拒绝模型传入原始数据库 ID；
- 句柄携带单调递增的内部资源版本，过期或记录已变化时返回 `STALE_PREVIEW`；
- 将 `body_weight_logs` 加入事务允许表、自检表/索引清单和外键完整性检查；
- 旧数据库通过追加迁移升级，不修改已经发布的 001–014；
- 0.6.1 的饮食、饮水、库存、报告和恢复行为保持兼容。

## 7. 本版本不做

- 月平均值、15 日均值；
- BMI、目标体重、健康评价；
- 按“空腹/睡前”等状态分别计算趋势；
- 图表、长期预测或自动减重建议；
- 自动部署或改写线上数据库。

这些能力只有在真实体重记录积累并验证数据质量后才进入后续路线图。
