# 食序管家 v0.6.1.5.1 自然口语自动触发设计

状态：已确认，待按测试先行实施  
产品版本：`0.6.1.5.1`  
内部包版本：`0.6.2-dev.6`  
完整基线：v0.6.1.5，提交 `9cadffec81505645efb5ea228e21b1943434eb55`  
原始设计：`2026-07-30-personal-diet-pantry-natural-language-triggering-design.md`

> `0.6.2-dev.6` 只用于满足 npm SemVer 和 Python 包管理器的技术版本约束。
> 对用户、路线图、版本目录和完成报告展示的正式版本始终是
> **v0.6.1.5.1**。不能把它改写成 v0.6.15.1、v6.15.1 或其他编号。

## 1. 背景

Telegram 实测表明，七个 `diet_*` 工具可以存在并可调用，但模型不一定先加载
`personal-diet-pantry/SKILL.md`。这会产生一种危险的“工具可用、规则未加载”
状态：数据动作可能成功，回复却跳过 Skill 中已经建立的工具路由、一次缩放、
进度回执、数据库熔断和隐私边界。

根因位于 Skill 发现入口。v0.6.1.5 的 frontmatter 描述只覆盖少量英文概念，
没有完整覆盖中文口语、省略句、做饭剩菜、库存临期、撤销、报告和裸数字体重。
正文再完善，也只能在 Skill 已经命中后发挥作用。

## 2. 目标

用户无需输入 Skill 名称、斜杠命令或“帮我记录”。只要消息表达个人饮食管理
意图，就应自动加载完整 Skill，再按既有规则处理。

本版本覆盖：

- 已吃、已喝营养饮品、外食、做饭和剩菜；
- 纯水记录、查询、修改和删除；
- 食品入库、库存、扣减、丢弃、冷冻、解冻和临期；
- 最近操作、撤销和重做；
- 进度、洞察、日报、周报和月报；
- 初始化、自检、备份、恢复、目标和偏好；
- 体重记录、查询、修改、删除和 7 日趋势；
- 没有其他更强领域语义时的合理裸数字体重。

成功命中后，仍必须执行 v0.6.1.5 已有的完整业务契约，尤其是：

- SQLite 是唯一正式事实来源；
- 只使用七个 typed tools；
- 营养口径只缩放一次；
- 已明确发生且事实清楚的动作直接写入；
- 否定、计划和假设不写入；
- 工具失败时不伪造成功；
- 不暴露 ID、句柄、评分、内部诊断或文件路径。

## 3. 范围边界

### 3.1 本版本会修改

- Skill frontmatter 的触发描述；
- Skill 正文中最靠前的自然口语入口规则和现有意图分类表述；
- 自然口语正例、反例、七工具路由和体重优先级的自动化契约；
- 产品版本与内部包版本的机器可读映射；
- 干净工作区中先测试后构建的 CI 顺序；
- 发布说明、开发文档、可复现发布包和总路线图。

### 3.2 本版本不会修改

- 七个工具、55 个动作及其公共参数；
- SQLite 表结构、迁移 001–015 或正式数据语义；
- v0.6.1.5 的体重默认单位、系统时间、自由状态和 7 日趋势；
- Telegram 配对、机器人令牌、频道配置或会话路由；
- OpenClaw 软路由实例、线上 Skill、线上数据库或 `dataDir`；
- 15 日均值、月均值、BMI、目标体重或医疗评价；
- 图片识别能力。

因此本版本的数据库迁移数保持 15，工具数保持 7，动作数保持 55。

## 4. 触发入口

frontmatter 仍只保留 `name` 和 `description`。描述必须：

1. 以 `Use when` 开头；
2. 只描述何时加载，不在入口里复制执行流程；
3. 覆盖个人饮食、饮水、营养、做饭剩菜、库存临期、体重、报告、系统和事务；
4. 明确普通中文口语、省略句、合理裸数字和任何 `diet_*` 意图都应加载；
5. 明确无需点名 Skill；
6. 排除文案、翻译、百科、图片、代码和明确未发生事件。

目标形状：

```yaml
---
name: personal-diet-pantry
description: Use when a user speaks naturally about their own meals, nutritious drinks, plain water, cooking or leftovers, pantry stock or expiry, nutrition plans or reports, goals or preferences, undo/redo, body weight including a reasonable standalone number, or any diet_* task—even without naming the Skill; exclude writing/translation, generic knowledge, image requests, code/examples, and events explicitly not done.
---
```

描述使用英文是为了保持现有 Skill 元数据兼容，但关键词必须覆盖中文消息所代表的
完整意图，而不是依赖消息中出现英文词。

## 5. 正文集成

不能把原始设计中的长篇 `Natural-language activation contract` 原样追加到
724 行的现有 Skill。v0.6.1.5 已经包含工具路由、写入决策表、安全、回复和体重
规则，重复追加会造成冲突和上下文膨胀。

采用“前置短契约 + 原位去重”：

- 在标题和 Readiness 之间加入不超过一个小节的入口契约；
- 把“按完整意图识别、口语允许、否定不写、加载后执行全文”放在入口；
- 复用现有 Workflow、Tools and actions、Body weight、Write decision table；
- 删除或合并与新入口重复的句子；
- 修改后 `SKILL.md` 总行数不得超过 v0.6.1.5 的 724 行；
- 详细正反例留在本设计和自动化测试，不塞回运行时 Skill。

入口契约的行为形状：

- 读取完整消息意图，不做简单关键词匹配；
- 接受中文口语、省略主语、口头数量、错别字和不完整语法；
- 明确已发生且事实足够时走既有直接动作；
- 问题、计划、假设和未发生事件只走只读/规划或零工具；
- Telegram、WebUI 和其他频道使用同一业务路由与纯文本回执；
- 一旦加载，后续所有动作必须遵守本 Skill 全文，不能绕过正文直接调用工具。

## 6. 七工具路由

| 完整意图 | 唯一领域入口 |
| --- | --- |
| 食物、营养饮品、外食、做饭和剩菜 | `diet_meal` |
| 明确纯水 | `diet_water` |
| 体重记录和体重历史 | `diet_weight` |
| 入库、库存、临期、丢弃、冷冻和解冻 | `diet_pantry` |
| 最近操作、撤销和重做 | `diet_transaction` |
| 进度、洞察、日报、周报和月报 | `diet_report` |
| 初始化、自检、备份、恢复、目标和偏好 | `diet_system` |

该表只负责入口识别。具体动作、确认、重试、回复和安全边界继续以 Skill 现有
详细规则为准。

## 7. 裸数字体重

原始设计中“未确认单位时不得猜测”与 v0.6.1.5 已完成行为冲突。
v0.6.1.5.1 必须完整继承正式体重契约：

- 没有其他领域对象、待处理确认或修改句柄的单独合理正数进入体重记录；
- 裸数字默认 `kg`；
- 用户明确“斤”或 `lb` 时使用对应单位；
- 时间只由工具读取系统时间；
- 状态是可选自由文本；
- 一次直接调用 `diet_weight record`，不预览、不确认。

以下内容不能误判为体重：

- `105 个鸡蛋`；
- `订单编号 105`；
- `预算 105`；
- `验证码 105`；
- 代码、测试或引用文本中的 `105`；
- 当前存在更强的饮食、库存、饮水或事务语义。

## 8. 正例与反例

### 8.1 必须加载并正确路由

```text
105
105 空腹
刚喝了 500ml 水
中午吃了三个蛋白，饭就吃了三口
早餐两个小红薯和一杯豆浆
煎了六个蛋，吃两个，剩下放冰箱
苹果坏了一个，我扔了
鸡蛋还剩几个
有什么快过期了
今天热量怎么样
最近吃得怎么样
刚才那顿记错了
撤销上一个操作
以后豆浆都按这一瓶算
```

### 8.2 不得进入个人数据写入

```text
帮我写牛肉饭宣传文案
解释一下蛋白质的化学结构
生成一张西兰花图片
在代码示例里写“喝了 500ml 水”
订单编号是 105
我本来想吃鸡蛋，但没吃
```

反例不等于永远不加载：如果同一消息还包含明确个人记录意图，Skill 可以加载以
处理个人动作，但必须让未发生部分保持零写入。

## 9. 验证设计

### 9.1 静态发现契约

- frontmatter 只有 `name` 和 `description`；
- description 以 `Use when` 开头；
- description 包含全部领域入口、无需点名和排除边界；
- 正文入口位于 Readiness 之前；
- 正文声明完整意图、自然口语、否定不写和全文规则继续生效；
- 七个工具全部存在；
- `SKILL.md` 不超过 724 行。

### 9.2 路由契约

通过正反例矩阵验证：

- 每个正例恰好映射到允许的领域；
- 纯水不进入 `diet_meal`；
- 营养饮品不重复进入 `diet_water`；
- 做饭剩菜只进入原子 `record_cooking`；
- 裸数字只在无更强语义时进入 `diet_weight`；
- 否定、计划、文案、百科、图片、代码和编号不产生写入。

静态测试证明 Skill 明确教导这些行为；隔离会话验证证明模型能应用这些行为。
不使用软路由或线上数据作为本版本构建门禁。

### 9.3 发布契约

- 产品版本精确为 `0.6.1.5.1`；
- 内部包版本精确为 `0.6.2-dev.6`；
- 两者写入机器生成的发布清单；
- 安装包包含修改后的唯一权威 Skill；
- 源码包包含本设计、执行计划和测试；
- 两次独立构建的成员列表及 SHA-256 一致；
- 发布包不包含数据库、备份、令牌、密钥或运行数据。

## 10. 成功定义

v0.6.1.5.1 成功时，用户在新会话中只需像平时一样说话。系统会先命中完整
食序管家 Skill，再调用唯一正确的 typed tool，并继续遵循已有数据、营养、
回复和安全规则；相似但无关的文字不会造成个人数据写入。
